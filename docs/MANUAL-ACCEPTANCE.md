# 人工驗收清單(必須在真實環境確認)

自動化測試全部在「假的 GAS 世界」中通過,以下項目必須用真實的 LINE、Gemini、TinyFish、Cloudflare 與 Google 帳號確認。建議依序進行,每項勾選並記下日期。

## A. 部署與授權

- [ ] `setupSheets` 執行成功,試算表出現 `Users`、`State`、`Archive`、`Events`、`Images`、`Logs` 六張表且各有標題列。
- [ ] **授權後重新部署新版本**(見 DEPLOY.md §5):在編輯器手動授權一次,再「管理部署作業 → 新版本」。之後傳一則訊息,`Logs` 與 `State` 不再出現權限錯誤(試算表與 Drive 都能存取)。
- [ ] `smokeTest` 回傳 `ok: true`(正規表示式 lookbehind、`\p{L}`、時區格式化在 Apps Script V8 中運作正常)。若有 `failures`,把清單貼回來處理。
- [ ] 網址密鑰:用瀏覽器開 `…/exec`(不帶 `?k=`)只看到「Webhook Verified」,不含任何設定;LINE 後台 Verify(帶 `?k=`)顯示成功;把 `?k=` 改錯後 Verify 失敗,且 `Logs` 只有一筆(限頻的)`BAD_KEY`。

## B. 白名單與基本對話

- [ ] 未登記的人傳訊息 → 收到「尚未開通。你的 ID 是 U…」。把 ID 填進 `Users`、執行 `refreshUsersCache` 後再傳 → 正常對話。
- [ ] **白名單新增與停用**:把 `enabled` 改成 `FALSE`(執行 `refreshUsersCache`)→ 回「尚未開通」;改回 `TRUE` → 恢復。
- [ ] 一次完整的「搜尋 → 回答」:問一個即時資訊(例如今天台北天氣)→ 回答合理、`Logs` 沒有 `SEARCH_FAILED`;再說「仔細查…」→ 多一次讀頁摘要;說「你可以上網查嗎」→ 不會直接搜尋。
- [ ] 回覆是純文字(沒有 `**`、`#`、程式碼圍欄),長回覆分成多則且在自然邊界切開。
- [ ] 隔一段時間再聊(或把 `State` 的最後互動時間調舊),機器人會自然問候、不把舊話題當剛剛的事。

## C. 事件去重、併發、鎖

- [ ] **重送同一事件**:在 LINE 後台或用工具對同一個 `webhookEventId` 重送 Webhook,只會有一次回覆與一次模型呼叫。
- [ ] **同時連發兩則訊息**(快速連續傳兩則):兩則都有回覆,事後對話歷史兩個回合都在(`State`/下一次對話的上下文可驗證)。
- [ ] 取不到鎖時(可用兩個分頁同時執行長任務模擬)reply 仍會送出,`Logs` 出現 `LOCK_TIMEOUT`。

## D. 圖片

- [ ] **先傳後問**:單獨傳一張圖 → 立刻收到「收到,想問什麼?」(沒有 AI 描述);10 分鐘內再傳文字提問 → 回答有參考圖片內容;再傳一則文字 → 不再帶圖。
- [ ] 連傳 3 張再提問 → 3 張都被參考;傳第 4 張時最舊的被丟掉。
- [ ] 傳一張超過 10MB 的圖再提問 → 回覆附註說明該張被略過。
- [ ] **圖片網址健檢**:執行 `checkImageUrls` → `summary` 回報主格式與備援格式都正常(測試檔在專用資料夾內建立、用完丟垃圾桶)。
- [ ] **手機 LINE 實際顯示生成的圖片**:要求「畫一張…」(需 `IMAGE_ENABLED=true` 與 Cloudflare 金鑰)→ 一則 reply 內文字在前、圖片在後,**用手機 LINE 確認圖片真的顯示**(不是破圖)。再用一個預期超過 1MB 的情境(提高 `IMAGE_WIDTH`/`IMAGE_HEIGHT`)確認備援格式的預覽圖也能顯示。
- [ ] Drive 的**專用資料夾**(`IMAGE_DRIVE_FOLDER_ID`)中出現生成的檔案,檔名只有時間戳(不含你的提示詞),分享設定為「知道連結的人可檢視」;**Drive 根目錄沒有新檔案**。
- [ ] 把 `IMAGE_DRIVE_FOLDER_ID` 暫時清空 → 要求「畫一張…」時機器人婉拒、沒有呼叫 Cloudflare(Cloudflare 用量不增加)、Logs 有 `KEY_MISSING`(detail 為 `IMAGE_DRIVE_FOLDER_ID`);還原設定後恢復正常。
- [ ] 把 `IMAGE_DRIVE_FOLDER_ID` 暫時改成不存在的 ID → 回覆「圖片已產生但無法儲存」、Logs 有 `IMAGE_DRIVE_FAILED`、Drive 沒有任何新檔案(含根目錄);還原後恢復正常。
- [ ] 額度與冷卻:把 `IMAGE_MAX_PER_DAY` 暫設 1、`IMAGE_COOLDOWN_S` 暫設 30,連續要求兩次 → 第二次被婉拒並說明;跨過 UTC 午夜(台灣早上 8 點)後恢復。
- [ ] (可選)超過 `IMAGE_RETENTION_DAYS` 的舊圖在下一次成功生圖時被丟進 Drive 垃圾桶(可把 `Images` 表中某列的 `created_at` 改成很久以前來測)。
- [ ] (可選)**只清理專用資料夾**:在 Drive 根目錄另放一個測試檔,把它的 ID 加進 `Images` 表(`created_at` 設很久以前、`trashed` 為 0),成功生圖後確認該檔**沒有**被丟垃圾桶、該列 `trashed` 仍為 0。

## E. 群組

- [ ] **群組 @ 行為**:把機器人加進群組。未登記時 @ 它 → 「此群組尚未開通,群組 ID 是 C…」;沒 @ 的訊息完全沒有反應。登記後 @ 它 → 正常回覆(回覆中沒有「@名稱」字樣被當成問題內容)。
- [ ] 群組內非 `Users` 表成員被 @ 也能使用;群組的對話與個人聊天室互不影響(在群組說的話,私聊時機器人不會知道,反之亦然)。
- [ ] 群組傳圖(不 @)→ 機器人沒有任何反應;接著 @ 機器人提問 → 有參考該圖。
- [ ] 群組內 `/忘記`:`Users` 表內的成員可以清空群組;不在表內的成員被拒絕。

## F. 記憶

- [ ] 把 `HISTORY_MAX_TURNS` 暫設 4、`FOLD_BATCH_TURNS` 暫設 2,連聊 5 輪以上 → `Events` 出現日誌事件、`Archive` 出現被整理的原文、`State` 的 `facts` 有內容;`Logs` 沒有 `FOLD_INVALID`(若有,檢查輔助模型是否支援結構化輸出)。
- [ ] 隔一天後聊到之前的話題,機器人能想起相關內容(檢索);`/記憶` 顯示長期事實與事件數量。
- [ ] **`/忘記` 確認流程**:第一次只回確認說明;超過 `FORGET_CONFIRM_TTL_S` 才輸入無效;在時限內再輸入一次 → 清空;之後對話從頭開始,`Events`/`Archive` 中屬於該聊天室的列被刪除、其他聊天室不受影響。
- [ ] 搜尋過的回合(用到網頁內容)整理後,`Archive` 中那一列的 `polluted` 為 1 且內容是「(那天查過…;網頁內容未納入)」佔位文字。
- [ ] 在 `Archive`、`Events` 手動貼一個以 `=` 開頭的字串(例如 `=1+1`)確認顯示為純文字而不是計算結果(這兩張表應為純文字格式)。

## G. 時間成本與存取預算

- [ ] 把 **`DEBUG_TIMING` 設為 `true`**,傳幾則訊息(含一次「冷啟動」:等數分鐘讓快取與執行個體冷掉),再到 `Logs` 讀 `TIMING` 列:**記下冷啟動時第一次開啟試算表(`sheet.open`)的實際耗時**,以及各次 `sheet.read`、`http …` 的耗時。
  - 若 `sheet.open` 在冷啟動時就接近或超過 1–2 秒,判斷是否要把「使用者 + 狀態 + 事件 + 歸檔」的讀取再合併(目前它們已是連續的一個讀取階段)。
  - 確認熱請求(快取命中)沒有 `sheet.read` 列。
  - 驗完把 `DEBUG_TIMING` 改回 `false`。
- [ ] 實際觀察一次含搜尋的回合總耗時是否在 `TIME_BUDGET_S`(預設 60 秒)內;若常逼近,調高 `TIME_BUDGET_S` 或降低 `MAX_TOOL_TURNS`。

## H. 例外情況

- [ ] 暫時把 `GEMINI_API_KEY` 改錯 → 使用者看到「發生錯誤」類的固定句子,`Logs` 有 `GEMINI_FAILED`,日誌與回覆中**沒有任何金鑰**。改回後恢復。
- [ ] 把 `LINE_CHANNEL_ACCESS_TOKEN` 改錯 → `Logs` 出現 `LINE_REPLY_FAILED`(附 HTTP 狀態與 LINE 回應的 message 欄位)。(若設定 `PUSH_MONTHLY_BUDGET` > 0 會嘗試 push 補送,同樣會失敗。)
- [ ] 傳貼圖、語音、影片、檔案、位置 → 機器人完全沒反應(靜默忽略),`Logs` 沒有錯誤。
